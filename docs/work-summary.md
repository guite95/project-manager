# 작업 정리와 work-sum

`/today/history`에는 **완료 기록**과 **작업 정리**가 있다. 완료 기록은 체크한 순간의 원본 이력이고, 작업 정리는 Git 커밋과 완료 기록을 합쳐 정리한 날짜별 스냅샷이다.

작업 정리에서 날짜를 선택하면 프로젝트별 작업과 각 작업의 근거를 볼 수 있다. 기존 오늘의 할 일에 있던 **작업내용 복사** 버튼은 이 탭으로 이동했다. 선택한 날짜의 정리된 프로젝트명과 작업 제목을 화면과 같은 순서로 복사한다. 공통 프로젝트도 목록에 있으면 포함하며 커밋 해시, 수집 상태, 제외 사유는 복사하지 않는다. 정리가 없거나 작업이 0건이면 복사할 수 없다.

## 설치와 사용

```sh
node skills/work-sum/scripts/install.mjs
```

- Codex: `$work-sum 오늘 작업 정리해줘`
- Claude: `/work-sum 오늘 작업 정리해줘`
- 과거 날짜: `work-sum으로 2026-09-14 작업을 정리해서 완료 이력에 저장해줘`

실제 스킬은 저장소의 `skills/work-sum`, 개인 설치는 `~/.agents/skills/work-sum` 및 `~/.claude/skills/work-sum` 심볼릭 링크다. 저장소 의존성이 필요하다. [실행 명령](../skills/work-sum/references/commands.md), [JSON 형식](../skills/work-sum/references/format.md)을 참조한다.

## 수집과 중복 정리

기본 루트는 `~/Documents/project`. 하위의 중첩 Git 저장소도 찾으며 숨김/빌드/의존성 폴더와 심볼릭 링크는 탐색하지 않는다. 모든 로컬 ref와 HEAD에서 한국 시간 하루의 **커미터 날짜**에 해당하고 저장소의 `user.email`과 작성자가 일치하는 커밋을 읽는다. 여러 작성자 이메일은 `--authors`로 지정한다. 미커밋 작업, reflog에만 있는 커밋, 아직 fetch하지 않은 원격 이력은 포함되지 않는다. 수집은 Git을 변경하지 않는다.

앱 자료는 현재 Issue.done이 아니라 날짜별 Completion 스냅샷을 사용한다. 다른 날로 넘어간 완료 체크도 남는다. 저장소 경로 구간이 프로젝트 slug와 정확히 일치하는 경우에만 자동 연결하고, 나머지는 독립적인 미연결 그룹으로 표시한다. 사용자가 제공한 연결은 `--mapping`으로 지정한다. 같은 공통 Git 저장소의 워크트리는 한 번 수집하고 매핑도 함께 적용한다.

의미상의 중복은 에이전트가 판단한다. 동일 프로젝트·동일 결과의 구현/수정/완료 체크를 묶고 비개발 완료 작업도 유지한다. 검증기는 모든 증거 ID가 작업 또는 제외 사유에 한 번씩 배정되었는지, 서로 다른 프로젝트를 합치지 않았는지 검사한다. 제목의 사실성은 에이전트가 검토한다. 커밋만으로 테스트·배포·업무 전체 완료를 단정하지 않는다.

## 저장 계약

별도 스키마 변경 없이 `app_setting`의 `work-summary:YYYY-MM-DD`에 version/revision/savedAt/evidence/summary를 저장한다. 완료·이슈 원본은 수정하지 않는다. 날짜별 최신 결과 하나를 보여주며 새로 저장하기 전 이전 값을 기본 `~/pm-backups`에 해시를 검증한 백업으로 보관한다. 수집 당시 revision과 저장할 때 revision이 다르면 충돌로 중단한다. 재정리는 새 증거 수집부터 다시 실행한다.

DB 명령은 기존 공유 DB 래퍼를 사용한다. CLI 직접 연결은 안전 검증한 로컬 `project_management_test`만 허용한다. 입력 파일의 SHA-256은 검토 후 파일 변경을 잡는 장치이며 내용의 의미를 검증하는 서명은 아니다. 저장된 결과는 수집 시점의 스냅샷으로 자동 갱신하지 않는다.

- GREEN: 같은 시나리오에서 실제 validate 성공. Alpha 구현/수정/완료 3개 증거 통합, 별도 프로젝트 분리, 비개발 작업 보존, 미연결 저장소 유지, 단순 merge 제외. 4개 작업·1개 제외.
- Edge: 루트 자체 저장소의 `.` 매핑 및 워크트리 매핑 누락을 재현하고 수정했다. 회귀 테스트 포함.
- 로컬 테스트 DB에서 CLI 수집→검증→백업→저장, 파일 해시 불일치, 이전 버전 저장, 동시 저장 충돌, 원본 완료 기록 보존을 확인했다.
- 별도 테스트 DB에 연결한 빌드 서버에서 브라우저의 정리 표시, 근거 펼치기, 실제 클립보드, 모바일 가로 넘침 없음, 빈 결과 복사 비활성화, 기존 두 화면의 복사 버튼 제거를 확인했다.
- 실제 `~/Documents/project` 저장소 10개의 읽기 전용 Git 수집 성공. 공유 DB에 실제 일일 결과를 저장하거나 배포하지 않았다.

- 최종 집중 테스트 45개, `pnpm typecheck`, `pnpm build` 통과. Codex skills/list에서 활성 사용자 스킬로 확인했고 Claude의 Read 실행에서 동일 스킬 이름·기본 루트·저장 화면을 확인했다.
