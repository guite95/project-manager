# 개인 프로젝트 기록

개인 사이드바는 프로젝트별 메뉴로 진입한다. 전체 프로젝트 목록 링크는 표시하지 않으며 `/personal`은 프로젝트 선택 안내와 프로젝트 추가만 제공한다. 각 프로젝트의 기록 메뉴는 자료·회의록·구조도 다음, 가장 아래에 둔다. 프로젝트 이름과 저장소 수정은 기록 화면의 프로젝트 수정 버튼에서 가능하다.

`/flows/<project>/notes`의 개인 프로젝트 화면은 다음을 작성·조회한다.

- 프로젝트 개요: 만든 목적, 기간, 참여 인원, 내가 맡은 범위
- 작업별 제목과 요약, 주요 작업, 문제와 판단, 구현과 결과, 근거

작업 목록에서 항목을 선택해 상세를 읽는다. 편집과 작업 추가 후 저장해야 반영된다. 직접 수행한 범위, 테스트, 배포, 효과와 한계를 구분해 기록한다. 채용 경험정리와는 별개의 상세 기록이며 자동 복사·동기화하지 않는다.

공유 `app_setting`의 `project:records:<slug>`에 개요와 작업 배열, revision, updatedAt을 저장한다. 서버 세션의 OWNER 및 DB의 PERSONAL scope를 확인한다. `/api/personal-project-records/<project>` GET은 선택한 프로젝트만 읽고 키를 생성하지 않는다. PUT은 same-origin JSON, 입력 크기, 작업 ID 중복과 제목을 검증하고 예상 revision 및 JSON 비교 갱신으로 충돌을 거절한다. 충돌·네트워크 오류가 나도 화면의 작성 내용은 유지되고 복사할 수 있다. 편집 중에는 자동 조회가 내용을 덮어쓰지 않는다. 읽기 모드는 창 복귀와 표시 중 15초 간격으로 갱신한다.

기존 `project_note`는 변경하지 않으며 개인 기록 화면 하단의 ‘이전 메모’에서 읽을 수 있다. 공통 명심할 점의 기존 메모 편집기는 유지한다. 본문은 React 일반 텍스트로 렌더링한다. localStorage 저장이나 DB 스키마 변경은 없다. 운영 DB 데이터 등록 및 배포는 별도 작업이다.

검증은 `lib/project-records.test.mjs`, `lib/server/project-records-store.test.mjs`와 기존 메모·프로젝트 권한 테스트, 타입 검사, 빌드로 수행한다. DB 테스트는 `lib/server/test-db.mjs`가 허용하는 로컬 테스트 DB에서만 실행한다. 브라우저 검증은 명시 요청 시 수행한다.
