## 읽는 법과 표시 규약

- 실선 `impl`: 실제 코드로 확인한 현행 실행 연결. 설계 `future`: 구현이 필요한 목표 흐름. 참조 `ref`: 일정·원천·결과 관계이며 실행 순서가 아님.
- 현행 계산서→SALES 실선과 목표 출고→매출 점선은 전환 전후다. 동시에 두 SALES 전표를 만드는 설계가 아니다.
- 본문 섹션은 **화면 / 기능 / 회계 처리 / 확인 사항**만 쓴다. 화면은 실제 사용자 화면 노드에서만 상단 배너로 표시한다. 로직 노드는 화면 섹션을 갖지 않는다.
- 기능: 화면 노드에서는 사용자 행동, 로직 노드에서는 자동 처리. 회계 처리에는 실제/목표 분개를 쓰며 없는 경우 `없음`.
- 단계 번호는 제거했다. A·B·C는 조건 이름이며 단계 순서가 아니다.
- A/B는 기본/예외 관계를 제목과 연결선에서 명시하며, `layoutOnly` 그룹으로 인접 배치한다. 외곽 회색 박스는 표시하지 않는다.
- `payment-gate`는 해당 A **또는** B **또는** C의 OR 합류, `ship-gate`는 조달 준비 **그리고** 결제조건 충족의 AND 합류다.
- `installment→bank`는 회차 예정 참조선이다. 계약 시점에 채권 수금이 실행된다는 뜻이 아니다.

## 분개와 세액

- **현행 SALES**: 차 매출채권(공급가+세액), 대 계약별 매출(공급가)+부가세예수금(세액). 계약이 여럿이면 매출 라인도 여러 개이며 세액 0이면 VAT 라인은 생략한다.
- **현행 RECEIPT**: 차 은행 계정(배분 합), 대 계산서별 매출채권. 매출·부가세 재인식 없음.
- **현행 수금 취소**: 원 RECEIPT를 반전. 실제 은행 환급 실행과 구분한다.
- **현행 COGS**: 차 계약별 매출원가 / 대 재고자산 합계. 출고 실적과 같은 트랜잭션.
- **설계 선수금 수취·영수 발행**: 차 예금 또는 고객카드정산채권(총액), 대 선수금(공급가)+부가세예수금(세액). 수취 노드와 영수 발행 노드는 동일 회계 이벤트를 설명하며 각각 중복 분개하지 않는다.
- **설계 출고 매출**: 차 선수금(충당 공급가)+매출채권(미수 공급가·세액), 대 출고 매출(전체 공급가)+부가세예수금(아직 발행하지 않은 세액). 이미 영수 발행 때 인식한 세액을 다시 인식하지 않는다. 초과 선수금은 잔액 유지. 미수액이 있을 때만 채권.
- 반품·취소는 수정세금계산서·부가세·매출·채권·선수금·환급을 원거래에 연결한다. 출고 역실적 원가 되감기는 현행이고, 일반 실물 반품 입고와 증빙 통합 경로는 설계다.

## 선행 과제·축 충돌

1. **계약 생성**: 업무는 계약 생성 → 진행 → 계약 확정 순서다. 확정은 이미 생성된 계약의 상태 전이이며 행 생성 시점이 아니다. 기준 코드의 첫 출고 시 contracts 생성은 계약 생성 시점으로 앞당겨야 출고 전 선수금·영수 발행이 성립한다.
2. **선수금 발행**: 출고 실적 계약만 허용하는 가드를 개정하고 청구/영수 구분·계약/회차/수령 연결을 설계한다.
3. **출고별 발행**: 현행 계약 전량 발행 제약 및 계약/회차 연결만으로는 부족하다. 출고·라인별 증빙 연결과 기발행 수량/세액 검증이 필요하다.
4. **매출 트리거**: 계산서 생성→SALES를 출고→SALES로 이동. 증빙은 해당 출고 전표를 참조해야 한다.
5. **거래처 후불 예외**: 후불 허용 플래그와 계약 적용 기준 미구현. 여신 한도 필드가 있는 것처럼 표시하지 않는다. 현재 통제는 승인된 여신 예외 결재다.
6. **현장→계약 게이트**: 결제조건은 계약 성격+거래처, 현행 출고 게이트는 현장, 분할·계산서는 계약 축이다. 한 현장에 리테일·프로젝트가 혼재하면 판정 충돌 가능성이 있어 계약별 게이트로 이동한다.
7. **입고 전 예외출고 원가**: 실제 입고 시 원가를 연결하는 고리 미설계. 자동 소급 완료라고 표시하지 않는다.
8. **선수금 기발행분 정리**: 출고별 충당과 수정증빙 방법 미결. 공급가·세액의 중복을 금지하는 원칙만 확정한다.
