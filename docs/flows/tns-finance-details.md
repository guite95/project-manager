# 티앤에스 회계·재무 상세 흐름

기존 전체 요약에 업무별 상세 10개를 연결한 회계 확장 설계안이다. 모두 기존 `FlowChart` 선언과 React Flow/Dagre 가로 배치를 사용한다. 티앤에스 ERP 소스는 읽기만 했으며 실제 거래·DB·배포 상태를 변경하거나 검증하지 않았다.

## 차트와 업무 연결

| 상세 차트 | 담당자·원천 업무 | 회계·후속 결과 |

모든 업무의 원천 이벤트는 06의 전표·원장으로 연결된다. 01~04의 증빙은 05에서 대사하고, 07은 원장과 각 보조부를 받아 결산한다. 08·09는 기중 신고 경로이며 연말 결산을 기다리지 않는다. 07의 결산 초안과 10의 세무조정·세액 검토 결과를 대사한 뒤 최종 재무제표와 신고를 확정한다.

## 세무 흐름의 공개 근거

- 부가세는 매출세액과 매입세액을 바탕으로 계산하는 세목이다. 상세 차트에서는 증빙·공제 검토와 신고·납부를 분리했다. [국세청 부가가치세 개요](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7693&mi=2401)
- 소득 지급자의 원천징수·납부 및 소득 유형에 따른 지급명세서 의무를 고려해 급여 지급과 세무 제출을 연결했다. [국세청 원천징수 개요](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7701&mi=2413)
- 법인세 신고에 필요한 결산·세무조정 관련 서류를 고려해 결산, 세무 검토, 최종 신고 단계를 나눴다. [국세청 영리법인 신고 안내](https://www.nts.go.kr/nts/cm/cntnts/cntntsView.do?cntntsId=7979&mi=6553)

차트는 업무 설계이며 세율·신고기한·공제 요건을 고정하지 않는다. 회사 회계기준, 대상 세목·신고서식, 자산 인식·원가 기준, 승인 주체, 카드 정산 계약과 외부 세무 검토 체계는 상세 구축 시 확인한다. 직접 전자신고 지원을 전제하지 않고 신고파일·외부 신고도구를 포함한 제출 경로를 확정한다.

## 검증 범위

`pnpm typecheck`, `git diff --check`, 차트 10개의 slug·노드·엣지 중복 및 연결 유효성 검사를 통과했다. 로컬 프로젝트 매니지먼트 브라우저에서 상세 10개의 렌더링·전체화면·Esc 닫기와 사이드바 전환을 확인했다. 역방향 연결은 기존 그룹 레이아웃의 하단 우회선을 사용한다.

공통 메뉴 검색 입력의 빈 `style` 속성에 대한 hydration 경고가 반복 탐색 중 간헐적으로 관찰됐다. 요약과 법인세 차트를 별도 브라우저 컨텍스트에서 조회한 검증에서는 재현되지 않았고, 10개 연속 조회에서는 다시 관찰됐다. 차트 표시·전환 실패와 페이지 예외는 없었으며, 공통 셸 수정은 하지 않았다. ERP의 실제 회계 처리·DB·금융 연동·세무신고 동작은 검증하지 않았다.
