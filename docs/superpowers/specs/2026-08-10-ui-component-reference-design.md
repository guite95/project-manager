# 전체 프로젝트 UI 컴포넌트 레퍼런스 이식

- 날짜: 2026-08-10
- 상태: 설계 승인됨 (구현 전)
- 원본: `/Users/janguk/Documents/project/focusai/focusai/apps/web/app/(dev)/dev/ui`

## 목표

FocusAI의 개발용 UI 레퍼런스에 표시되는 업무 UI 형태를 프로젝트 매니지먼트
사이트로 이식한다. 색상은 현재 사이트의 `--bi-*` 토큰을 사용하고, 형태·밀도·
상호작용은 나중에 실제 프로젝트 화면에서 재사용할 수 있는 공통 컴포넌트로 둔다.

사용자는 기존 `/flows`의 “전체 프로젝트” 화면 안에서 프로젝트 목록과 UI
컴포넌트 레퍼런스를 전환해 확인할 수 있어야 한다. 데모는 별도 백엔드, API 또는
DB 없이 브라우저 로컬 상태만으로 동작한다.

## 선택한 접근

`/flows`에 `프로젝트`와 `UI 컴포넌트` 탭을 두고, 쿼리 파라미터로 선택 상태를
표현한다.

- `/flows`와 `/flows?view=projects`: 기존 프로젝트 목록
- `/flows?view=components`: UI 컴포넌트 레퍼런스
- 알 수 없는 `view` 값: 기존 프로젝트 목록으로 폴백

이 방식은 같은 “전체 프로젝트” 위치에서 확인할 수 있으면서도 긴 컴포넌트
레퍼런스가 프로젝트 목록을 항상 밀어내지 않는다. URL로 직접 다시 열거나 공유할
수 있고, 사이드바의 `/flows` 활성 상태도 유지된다.

검토한 다른 방식:

1. 프로젝트 목록 아래에 레퍼런스를 모두 이어 붙임: 한 화면이 지나치게 길어지고
   프로젝트 탐색이 불편해진다.
2. 별도 `/ui` 라우트와 사이드바 메뉴를 추가함: 구현은 단순하지만 사용자가 지정한
   “전체 프로젝트 쪽”이라는 정보 구조와 멀어진다.
3. `/flows` 안의 탭으로 분리함: 위치·가시성·화면 길이의 균형이 가장 좋아 채택한다.

## 화면 구조

사이드바의 `전체 플로우차트` 표기를 `전체 프로젝트`로 변경한다. `/flows` 본문은
다음 순서를 사용한다.

1. 페이지 제목과 한 줄 설명
2. `프로젝트 | UI 컴포넌트` 탭
3. 선택한 탭의 콘텐츠

`프로젝트` 탭은 기존 프로젝트·카테고리·플로우차트 카드 구조를 그대로 보존한다.
`UI 컴포넌트` 탭은 FocusAI 레퍼런스의 항목을 다음 순서로 모두 렌더한다.

1. 토큰 팔레트
2. 타이포그래피
3. 버튼
4. 입력과 폼
5. 배지
6. 필터와 기본 테이블
7. 관리형 테이블
8. 상세 모달

## 컴포넌트 경계

실제 재사용 가능한 요소와 레퍼런스 전용 예시를 분리한다.

- `components/erp/*`: 버튼, 배지, 검색형 선택, 폼 필드, 폼 레이아웃,
  필터 바, 데이터 테이블, 빈 상태, 섹션, 상세 모달과 관리형 컬럼 도구처럼
  이후 실제 업무 화면에서도 사용할 공통 컴포넌트
- `components/ui-reference/*`: 샘플 데이터와 각 레퍼런스 섹션의 조합
- `app/flows/page.tsx`: 탭·쿼리 파라미터 처리와 기존 프로젝트 목록 배치

현재 프로젝트의 `AppShell`과 사이드바는 유지한다. FocusAI의 앱 셸이나 고객 업무
데이터, 라우팅, API 클라이언트는 복사하지 않는다.

## 디자인 토큰 변환

FocusAI의 `--demo-*` 토큰 이름을 그대로 추가하지 않고 현재 프로젝트의 대응
`--bi-*` 토큰을 사용한다.

| FocusAI | 프로젝트 매니지먼트 |
| --- | --- |
| `--demo-accent` | `--bi-accent` |
| `--demo-accent-light` | `--bi-accent-light` |
| `--demo-background` | `--bi-bg` |
| `--demo-foreground` | `--bi-fg` |
| `--demo-muted` | `--bi-muted` |
| `--demo-border` | `--bi-border` |
| `--demo-card-bg` | `--bi-card-bg` |
| `--demo-sidebar-bg` | `--bi-sidebar-bg` |
| `--demo-sidebar-active` | `--bi-sidebar-active` |
| `--demo-table-header` | `--bi-table-header` |
| `--demo-success` | `--bi-success` |
| `--demo-warning` | `--bi-warning` |
| `--demo-error` | `--bi-error` |

컴포넌트의 12px 본문, 11px 보조 글자, 0~4px radius, 얇은 경계선, 평평한
surface와 고밀도 간격은 유지한다. 그림자나 독립적인 FocusAI 브랜드 색상은
추가하지 않는다.

## 로컬 상호작용과 상태

- 버튼: variant, size, disabled, loading 상태를 모두 표시한다.
- 폼: 텍스트, 일반 선택, 한글 포함 검색형 선택과 체크박스를 제어 상태로 둔다.
- 필터: 검색어와 상태 선택이 샘플 테이블 행을 실제로 필터링한다.
- 상세 모달: 열기·닫기, 탭 전환, ESC·배경 닫기, 포커스 복원과 레일 인라인
  편집을 지원한다. 저장은 짧은 로컬 지연으로 성공·오류 상태를 시연한다.
- 관리형 테이블: 컬럼 표시, 순서, 너비를 변경할 수 있다. 설정은 전용
  `localStorage` 키에 저장해 새로고침 뒤에도 유지한다.

어떤 데모 동작도 네트워크 요청을 만들지 않는다. 샘플 데이터는 레퍼런스 모듈
안의 고정 데이터이며 실제 고객 데이터나 FocusAI 업무 규칙을 포함하지 않는다.

## 오류와 복구

- 잘못된 `view` 쿼리는 프로젝트 탭으로 폴백한다.
- `localStorage` 접근이 차단되거나 quota 오류가 나면 현재 세션의 메모리 상태로만
  계속 동작한다.
- 저장된 컬럼 설정이 손상됐거나 현재 컬럼 목록과 맞지 않으면 유효한 값만
  정규화하고 빠진 컬럼은 기본 순서로 복구한다.
- 인라인 편집의 빈 필수값은 해당 행 가까이에 오류를 표시하고 이전 값을 유지한다.
- 모달과 팝오버는 닫힐 때 임시 편집 상태를 정리한다.

## 접근성

- 탭은 현재 선택 상태를 `aria-current` 또는 동등한 의미로 노출한다.
- 버튼, 검색, 선택, 체크박스와 컬럼 조절 핸들에 접근 가능한 이름을 제공한다.
- 모달은 `role="dialog"`, `aria-modal`, ESC 닫기, 초기 포커스, 포커스 순환·복원,
  배경 스크롤 잠금을 제공한다.
- 테이블은 caption과 semantic table 요소를 유지하고 숫자 열은 오른쪽 정렬한다.
- 포인터로만 가능한 핵심 동작을 만들지 않고 컬럼 순서 변경에 키보드 경로를 둔다.
