# 플로우차트 작성 가이드

이 프로젝트의 플로우차트는 **좌표를 손으로 찍지 않습니다**. 노드와 엣지를
선언 배열로만 적으면 [Dagre](https://github.com/dagrejs/dagre) 가 좌표를 계산하고,
[React Flow](https://reactflow.dev) 가 그립니다. 그래서 항목이 늘어도 배치가 깨지지
않습니다.

<Callout variant="info" title="한 줄 요약">
  **노드/엣지를 선언적 배열로만 정의** → **Dagre 가 좌표 자동 계산** →
  **kind(노드)·kind(엣지)·배지(시점/산출물)로 의미 표현**.
</Callout>

## 파일 구조

| 파일 | 역할 | 새 차트 만들 때 |
| --- | --- | --- |
| `components/flow/types.ts` | 선언 타입 (`FlowChart`, `NodeKind`, `EdgeKind`) | 안 건드림 |
| `components/flow/kind-style.ts` | kind → 카드 스타일 표 (노드·범례 공용) | 안 건드림 |
| `components/flow/flow-node.tsx` | 노드 카드 렌더 | 안 건드림 |
| `components/flow/group-node.tsx` | 그룹 박스 렌더 | 안 건드림 |
| `components/flow/layout.ts` | Dagre 2단 좌표 계산 + 엣지 kind→스타일 | 안 건드림 |
| `components/flow/process-flow.tsx` | 캔버스 · 전체화면 모달 | 안 건드림 |
| `lib/flows/<slug>.ts` | **플로우차트 데이터** | **여기만 작성** |
| `lib/flows/registry.ts` | 사이드바·목록·라우트의 단일 소스 | 한 줄 등록 |

## 새 플로우차트 추가하기

<Steps>
  <Step title="데이터 파일 만들기">
    `lib/flows/<slug>.ts` 에 `FlowChart` 를 선언합니다. 기존 파일
    (`delivery-lifecycle.ts`) 을 복사해서 시작하는 게 빠릅니다.

    ```ts
    import type { FlowChart } from "@/components/flow/types";

    export const myFlow: FlowChart = {
      slug: "my-flow",              // chart 쿼리파람 값
      title: "내 업무 흐름",
      description: "목록 카드에 뜨는 한 줄 설명",
      direction: "LR",              // LR(좌→우, 기본) | TB(위→아래)
      nodes: [
        { id: "start",  data: { kind: "intake", label: "요청 접수" } },
        { id: "review", data: { kind: "core",   label: "검토", sub: "담당자 배정" } },
        { id: "later",  data: { kind: "future", label: "자동화", doc: "규칙 정의서" } },
      ],
      edges: [
        { id: "e1", source: "start",  target: "review", kind: "impl" },
        { id: "e2", source: "review", target: "later",  kind: "future", label: "2단계" },
      ],
    };
    ```
  </Step>

  <Step title="레지스트리에 등록">
    `lib/flows/registry.ts` 의 `flowProjects` 에서 알맞은 프로젝트/카테고리의
    `charts` 에 넣습니다. 사이드바 트리, 목록 페이지, `/flows/<project>` 라우트가
    전부 여기서 파생되므로 **다른 등록 절차는 없습니다.**

    ```ts
    export const flowProjects: FlowProject[] = [
      {
        slug: "common",
        title: "공통",
        categories: [
          { slug: "delivery", title: "프로젝트 수행", charts: [deliveryLifecycle, changeControl, myFlow] },
        ],
      },
    ];
    ```
  </Step>

  <Step title="확인">
    `pnpm dev` 후 `/flows` 에서 카드로,
    `/flows/<project>?cat=<카테고리>&chart=<slug>` 에서 차트 화면으로 확인합니다.
  </Step>
</Steps>

## 섹션(그룹) 묶기

노드가 많아 섹션으로 나눠야 하면 `groups` 를 선언하고 노드에 `group` 을 답니다.

```ts
groups: [
  { id: "g-in",  label: "1. 유입", kind: "entry" },
  { id: "g-run", label: "2. 처리", kind: "deterministic" },
],
nodes: [
  { id: "start", group: "g-in",  data: { kind: "entry", label: "요청 접수" } },
  { id: "work",  group: "g-run", data: { kind: "deterministic", label: "처리" } },
],
direction: "TB",       // 그룹 박스끼리의 배치 방향
groupDirection: "LR",  // 그룹 "안쪽" 배치 방향 (기본값 = direction)
```

배치는 **2단**으로 돕니다. 먼저 그룹마다 내부 엣지만으로 Dagre 를 돌려 박스
크기를 확정하고, 그다음 그룹 박스와 그룹 밖 노드를 바깥 Dagre 로 배치합니다.

<Callout variant="warn" title="Dagre 의 compound 를 쓰지 않는 이유">
  Dagre 의 클러스터 기능은 박스를 **멤버의 바운딩 박스**로 잡습니다. 멤버가 여러
  rank 에 흩어지면 박스만 거대해지고 속은 텅 빕니다. 안쪽을 먼저 접어서 크기를
  확정하면 박스가 내용에 딱 맞습니다.
</Callout>

## 색 체계 규약

색은 전부 `app/globals.css` 의 `--bi-*` 토큰에서 옵니다. 컴포넌트에 색을 직접
넣지 않습니다. `kind` 는 **두 계열**이 있고, 한 차트 안에서는 한 계열만 쓰세요.
섞으면 색이 무엇을 뜻하는지 흐려집니다.

### 성숙도 계열 — "지금 도는가"

| 의미 | 노드 `kind` | 엣지 `kind` |
| --- | --- | --- |
| 진입점 (요청·유입·트리거) | `intake` — 흰 카드 + 회색 테두리 | — |
| 확정 단계 | `core` — accent 채움 + 흰 글자 | `impl` — 실선 |
| 예정·미확정 | `future` — accent 점선 + "예정" 배지 | `future` — accent 점선 |
| 기준정보 | `master` — 작은 회색 점선 | `master` — 회색 점선 |

### 도메인 계열 — "어떤 성격의 일인가"

아키텍처 다이어그램처럼 단계가 많고 성격이 갈릴 때 씁니다. 모두 옅은 배경 +
진한 테두리로 서로 대등하게 보입니다.

| `kind` | 의미 | `kind` | 의미 |
| --- | --- | --- | --- |
| `entry` | 사용자·웹·진입 | `gate` | 게이트·격리·승인 |
| `model` | AI 판독·모델 | `activate` | 활성화·완료·학습 |
| `deterministic` | 결정론 처리·조립 | `store` | 저장·큐·관측 |
| `verify` | 검증·감사 | `failure` | 실패·중단·위험 |

### 배지와 엣지 색

| 의미 | 표현 |
| --- | --- |
| 시점 (배치·마감) | ⏱ `timing` 배지 · `snapshot` 엣지(초록 점선) |
| 산출물 생성 | 📄 `doc` 배지 |
| 참조·공급·환류 | `ref` 엣지 (점선 + 화살표) |
| 엣지 색 지정 | `tone: "<kind>"` — 그 kind 의 색으로 선을 칠함 |

<Callout variant="info" title="배지 = 직교 정보">
  `kind` 는 노드의 **종류** 하나만 정합니다. 그 위에 **시점(`timing`)**·
  **산출물(`doc`)** 같은 직교 정보는 **배지**로 얹습니다. 한 노드가
  "확정 단계 + 주간 반복 + 주간보고 생성" 을 동시에 표현할 수 있습니다.
</Callout>

### 엣지 라벨 규칙

라벨은 선의 **중간 지점**에 그려집니다. 이웃한 두 노드 사이 간격은
`ranksep`(그룹 안쪽 70px)뿐이라, 그보다 넓은 라벨은 양옆 카드 글자를 덮습니다.

- **인접 노드 사이에는 짧은 라벨만** — 한글 6자 정도까지. 길어지면 카드를 가린다.
- **카드 본문이 이미 말하는 내용은 라벨로 반복하지 않는다** — 화살표 옆에
  같은 말을 또 쓰면 글자만 겹친다.
- 긴 설명이 필요하면 라벨 대신 **출발·도착 카드의 `sub`** 에 넣는다.

한 노드로 엣지가 여럿 모이거나 갈라질 때 선이 겹쳐 달리는 문제는
`layout.ts` 가 엣지마다 꺾이는 지점(`pathOptions.offset`)을 어긋나게 줘서
자동으로 처리합니다 — 선언 쪽에서 신경 쓸 것은 없습니다.

## 설계 원칙

- **좌표를 데이터에 넣지 않는다** — 손좌표는 항목이 늘면 반드시 겹친다. 배치는 Dagre 에 위임.
- **데이터 ⟂ 렌더 분리** — 흐름이 바뀌면 `lib/flows/*.ts` 배열만 고친다. 스타일 코드는 안 건드린다.
- **kind 는 하나, 직교 정보는 배지** — 색 폭발을 막고 의미를 합성 가능하게.
- **읽기 전용** — 노드 드래그·선택·연결을 전부 끈다. 이건 다이어그램이지 편집기가 아니다.
- **인라인 = 전체화면** — 같은 `<FlowCanvas/>` 를 재사용해 두 벌 관리하지 않는다.

## 인터랙션

- **트랙패드** — 두 손가락 스크롤 = 이동, 핀치 / <kbd>Cmd</kbd>+스크롤 = 확대
- **전체화면** — 캔버스 상단 바의 "전체화면" 버튼, <kbd>Esc</kbd> 로 닫기
- 우하단 컨트롤로 확대 / 축소 / 화면 맞춤
