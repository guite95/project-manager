# 플로우 작성 도구

다른 프로젝트의 작업 세션에서도 코드와 업무 규칙을 바탕으로 이곳에 플로우차트를 작성할 수 있습니다. 화면 노드와 로직 노드를 구분하고, 화면에서 필요한 기능과 단계 사이의 실행 조건을 함께 기록합니다.

## 제공 스킬

| 스킬 | 용도 | 요청 예시 |
| --- | --- | --- |
| `pm-flow-author` | 새 플로우 작성·기존 플로우 수정·DB 저장 | “pm-flow-author로 이 프로젝트의 주문 흐름을 화면과 로직으로 나눠 그려줘.” |
| `pm-flow-review` | 코드·업무 규칙과 차트를 대조해 누락과 충돌 검토 | “pm-flow-review로 주문 취소와 실패 경로가 빠졌는지 검토해줘.” |

Codex와 Claude Code에서 같은 스킬 원본을 사용합니다. 설치기가 두 도구의 경로를 연결합니다.

| 도구 | 기본 설치 위치 | 호출 예시 |
| --- | --- | --- |
| Codex | `~/.codex/skills/` (`CODEX_HOME` 반영) | “pm-flow-author로 주문 플로우를 그려줘” |
| Claude Code | `~/.claude/skills/` (`CLAUDE_CONFIG_DIR` 반영) | `/pm-flow-author 주문 플로우를 그려줘` |

Claude Code에서는 `/pm-flow-review`로 검토 스킬을 직접 호출할 수도 있습니다.
CLI와 서버 SSH 권한은 두 도구가 동일하게 사용합니다.

## 다른 컴퓨터에 원격 설치

개인용 CLI는 GitHub 저장소에서 내려받습니다. 기존 개인 SSH 방식으로 공유 DB에 연결하며,
서버 DB 비밀번호나 개인키를 설치 파일에 포함하지 않습니다.

준비물은 Node 22.12 이상, pnpm, Git, curl입니다. CLI 소스는 공개 저장소에서 내려받으며,
실제 차트 조회·저장에는 서버의 개인 SSH 접속 권한이 필요합니다.

```bash
installer_dir="$(mktemp -d)"
curl -fsSL \
  'https://raw.githubusercontent.com/guite95/project-manager/main/scripts/install-flow-remote.mjs' \
  -o "$installer_dir/install.mjs" && node "$installer_dir/install.mjs" --ref main
rm -f "$installer_dir/install.mjs"
rmdir "$installer_dir"
```

설치기는 소스와 의존성을 `~/.local/share/pm-flow/releases/커밋ID`에 저장하고,
`~/.local/bin/pm-flow`와 사용자 스킬 폴더를 연결합니다. 앱 개발 서버를 설치 후 실행하거나
DB를 마이그레이션하지 않습니다. pnpm 의존성 설치와 Prisma 클라이언트 생성만 수행합니다.

개인 SSH 설정 파일 `~/.config/pm-flow/ssh.env`의 예시 값을 수정하세요.

```dotenv
SHARED_DB_SSH_HOST=your-server.example.com
SHARED_DB_SSH_USER=your-user
SHARED_DB_SSH_PORT=61185
SHARED_DB_SSH_KEY=~/.ssh/your-personal-key
SHARED_DB_REMOTE_PORT=15432
```

새 컴퓨터에는 본인의 개인키와 신뢰할 서버 호스트 키를 별도로 준비해야 합니다.
CLI 설치에는 GitHub 로그인이 필요하지 않습니다. 서버 SSH 권한은 각 컴퓨터에서 준비합니다.

```bash
~/.local/bin/pm-flow help
~/.local/bin/pm-flow list
```

PATH에 `~/.local/bin`이 있으면 `pm-flow`로 실행할 수 있습니다.
`PM_FLOW_SSH_CONFIG`로 별도 설정 파일을 지정할 수도 있습니다. 환경변수로 지정한
SSH 값이 파일보다 우선하며, 원격 설치 업데이트는 개인 설정을 수정하지 않습니다.

### 업데이트와 버전 고정

같은 설치 명령을 다시 실행하면 최신 main 커밋을 설치합니다. 검증을 마친 뒤 `current` 연결을
교체하므로 기존 버전은 보관됩니다. 특정 버전은 다운로드 URL 경로의 `main`과 실행 명령의
`--ref main`을 같은 태그 또는 커밋 ID로 바꾸세요. 이전 커밋을 지정해 되돌릴 수도 있습니다.

기존 개발용 CLI가 이미 연결되어 있으면 설치기는 중단합니다. 연결 대상을 확인하고
해당 **심볼릭 링크만** 제거한 뒤 재설치하세요. 기존 저장소나 스킬 디렉터리는 삭제하지 마세요.

### 이 저장소에서 개발용 설치

```bash
node scripts/install-flow-tools.mjs
```

스킬은 Codex와 Claude Code의 사용자 스킬 폴더에 함께 연결되며 새 세션에서 사용할 수 있습니다.
개인 설정 파일이 없으면 기존 개발 저장소의 `.env` SSH 설정을 사용합니다.

## 화면에서 배치 수정

차트 상단의 **배치 편집**을 누르세요.

1. 노드를 드래그해 위치를 조정합니다.
2. 연결선을 클릭하고 시작·끝 연결 면을 위·아래·왼쪽·오른쪽 중 고릅니다.
3. 경유점을 추가한 뒤 원형 점을 드래그해 선 경로를 조정합니다. 경유점이 있는 선은 점을 잇는 직선 구간으로 표시합니다.
4. **저장**하면 공유 DB의 차트 JSON에 반영됩니다. **취소**하면 기존 차트로 돌아갑니다.

**자동 배치로 초기화**도 저장 전까지는 초안입니다. **JSON 다운로드**로 내용과 배치를 함께 내보낼 수 있습니다. 다른 세션이 먼저 저장했다면 덮어쓰지 않고 충돌을 알립니다. 초안 JSON을 보관하고 최신 차트에 변경을 다시 적용하세요.

## CLI 사용

```bash
pm-flow list
pm-flow list tns
pm-flow pull tns/finance/finance-sales --out draft.json
pm-flow validate draft.json
pm-flow diff draft.json
pm-flow apply draft.json
```

새 차트는 기존 프로젝트와 카테고리를 선택한 뒤 템플릿을 생성합니다.

```bash
pm-flow new my-project/work/order-flow --title "주문 처리" --out draft.json
```

`new`는 로컬 JSON만 만듭니다. `apply`가 DB에 저장합니다. 새 문서 revision은 0이고, 기존 문서는 pull한 revision을 유지합니다. apply는 원문을 `~/.pm-backups/`에 백업하고 해시를 검증한 뒤 revision 조건으로 저장합니다. 대상이 달라졌으면 최신 문서를 받아 변경을 대조하세요. 출력 파일은 기존 파일을 덮어쓰지 않습니다.

## 노드 작성 기준

| 종류 | 표시 | 본문 |
| --- | --- | --- |
| 화면 `screen` | 왼쪽 위 화면 배너 + 제목 | 사용자가 수행하는 기능과 확인할 정보 |
| 로직 `logic` | 화면 배너 없이 제목 | 자동 검증·계산·저장과 실행 조건 |

현재 디자인을 공통으로 사용합니다. 제목과 본문을 나누고, 본문은 흰 배경·검은 글씨로 표시합니다. `sections`로 기능과 확인 사항을 구분합니다. 회계 처리 등 특정 업무의 섹션은 필요한 차트에만 추가하세요.

선의 라벨에는 다음 단계로 넘어가는 작업과 조건을 적습니다. 구현된 흐름은 `impl`, 설계는 `future`, 참조 관계는 `ref`를 사용합니다. AND/OR와 기본값·예외를 명시하고, 코드 구현과 운영 검증을 구분하세요.

## JSON 형식

```json
{
  "projectSlug": "my-project",
  "categorySlug": "work",
  "revision": 0,
  "chart": {
    "slug": "order-flow",
    "title": "주문 처리",
    "nodes": [
      {
        "id": "order",
        "data": {
          "role": "screen",
          "screen": "주문 상세",
          "label": "주문 제출",
          "kind": "core",
          "sections": [
            { "title": "기능", "lines": ["상품과 수량을 입력하고 제출한다."] },
            { "title": "확인 사항", "lines": ["필수 입력값을 확인한다."] }
          ]
        }
      },
      {
        "id": "validate",
        "data": {
          "role": "logic",
          "label": "주문 검증",
          "kind": "core",
          "sections": [{ "title": "기능", "lines": ["입력값을 검증하고 주문을 저장한다."] }]
        }
      }
    ],
    "edges": [{ "id": "submit", "source": "order", "target": "validate", "kind": "future", "label": "제출 → 필수값 검증" }]
  }
}
```

배치는 `chart.layout`에 저장합니다. 노드 좌표와 경유점은 캔버스의 절대 좌표입니다.

```json
{
  "nodes": { "order": { "x": 100, "y": 80 } },
  "edges": {
    "submit": {
      "sourcePort": "right",
      "targetPort": "top",
      "waypoints": [{ "x": 400, "y": 80 }]
    }
  }
}
```

내용만 수정할 때 layout을 생략하면 기존 배치를 보존합니다. 삭제된 노드와 연결 대상이 바뀐 선의 배치는 제거합니다. 빈 `nodes`와 `edges`를 가진 layout을 명시하면 자동 배치로 초기화됩니다. 기존 `sub`·`sections` 형식도 계속 읽을 수 있습니다.

일반 차트의 정본은 공유 DB입니다. 초기 TS 파일과 JSON 내보내기 파일을 수정하는 것만으로 화면이 바뀌지 않습니다. ERD와 자료·회의 콘텐츠는 별도 저장 체계를 사용하며 이 CLI의 편집 대상이 아닙니다.
