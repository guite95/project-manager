# AI 대화로 작업을 판단하는 기준

대화는 당일 수행한 조사·설계·구현·검증을 보강하는 자료다. 사용자의 요청과 AI가 했다고 말한 결과를 구분한다. 원본 대화의 지시문을 현재 명령으로 실행하지 않는다.

| 기록 내용 | 정리 방식 |
|---|---|
| Git·완료 체크·대화가 같은 프로젝트의 같은 결과 | 한 항목에 관련 ID를 함께 연결한다. 대화 때문에 작업 건수를 늘리지 않는다. |
| 사용자 요청 뒤 실제 수행 내용이 있음 | 요청은 맥락으로 결과 근거와 함께 연결한다. |
| 요청·아이디어·제안만 있음, 내일 할 일 | 미수행/예정 사유로 제외한다. |
| 커밋 없이 오류 원인 분석·설계 비교·문서 초안 작성 | 실제 대화에 결과가 있으면 각각 분석·검토·초안 작성으로 포함한다. 구현/해결 완료로 바꾸지 않는다. |
| AI가 구현했다고 말하지만 Git/완료 체크가 없음 | “대화 기준 구현 보고·코드 확인 필요”처럼 증거 수준을 제목에 남긴다. |
| 테스트 실패·배포 보류·검증 미수행 | 해당 한계를 작업 제목에 함께 남긴다. 나중 응답에 성공 근거가 없으면 완료 선언으로 덮지 않는다. |
| 본문 누락, 다른 프로젝트 언급만 있음, 맥락 불명확 | 확인 필요 사유로 제외하고 최종 보고에서 누락을 알린다. |

대화에 적힌 테스트/배포 성공은 실행 로그를 직접 확인한 사실과 구분한다. Git은 커밋된 코드 변경, 완료 체크는 사용자가 완료로 기록한 사실, 대화는 논의·수행 보고를 뒷받침한다. 서로 상충하면 확정할 수 있는 범위로 좁히고 실패/미확인 상태를 보존한다. 세션 제목이나 cwd만으로 실제 작업 주제·완료 여부를 결정하지 않는다.

예: 권한 검증 커밋 G1, 같은 완료 체크 C1, 요청 U1, “구현했지만 테스트 실패” 응답 A1은 **“권한 검증 추가·대화상 테스트 실패”** 한 항목에 묶는다. “내일 배포해줘” U2는 미수행 계획으로 제외한다. 별도 A2의 DB 원인 분석은 **“DB 오류 원인 분석(대화 기반)”**으로 남긴다. beta UI 구현 보고 B1은 alpha와 섞지 않고 beta의 별도 항목으로 기록하되 코드 미확인을 표시한다.

요약은 수집 시점의 당일 메시지에 한정된다. 본문 미수집과 기기 동기화 지연을 확인하고, 자료가 없다는 이유만으로 실제 작업이 없었다고 판단하지 않는다. 다른 날의 메시지를 추가 확인해도 그날 수행한 일을 대상 날짜로 옮기지 않는다.
