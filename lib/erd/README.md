# 티앤에스 ERD

`tns-schema.json`은 TNS Trading의 로컬 Prisma 스키마 스냅샷이다. 운영 DB를 조회하지 않으며 실제 레코드나 컬럼 기본값은 복사하지 않는다. 캡처 날짜와 스키마 SHA-256으로 기준을 확인한다.

재생성:

```sh
node scripts/generate-tns-erd.mjs /path/to/tnstrading/apps/web/prisma/schema.prisma
node --test lib/erd/*.test.mjs
pnpm typecheck
```

`tns.ts`의 업무 영역 분류로 ERD를 구성한다. 각 영역은 소속 테이블에서 나가는 모든 FK와 참조 대상 테이블을 표시한다. 테이블 집중 보기는 들어오는 FK도 포함한다. 화면에는 PK·FK 컬럼을 표시하며 전체 컬럼과 복합 PK/UQ 제약은 상세 표에서 확인한다.

## 화면 배치와 관계 강조

- 최초 배치는 `layout.ts`에서 연결이 가까운 테이블을 최대 6개씩 묶고, 다른 영역의 참조 대상은 영역별로 구분해 생성한다. 각 묶음과 전체 화면은 가로 공간을 활용하도록 약 16:10 비율을 목표로 배치한다. 생성 결과는 DB에 저장하며 일반 플로우차트는 기존 Dagre 배치를 사용한다.
- `routes.ts`는 테이블 좌우 연결점을 관계별로 나누고 카드 사이 여백으로 직각 경로를 찾는다. 모든 FK와 자기 참조를 유지하며 필수/선택 참조의 실선/점선을 보존한다. 선끼리 교차하거나 같은 통로를 일부 공유할 수 있다.
- 테이블 클릭과 영역 내 드롭다운 선택은 전체 배치를 유지하며 해당 테이블과 직접 연결된 선을 강조한다. 전체 보기에서는 관계 숫자를 숨기고 강조한 관계에만 표시한다.
- **선택 테이블 연결만 보기**는 기존 집중 보기로 전환해 들어오고 나가는 FK를 모두 표시한다. 영역 밖 테이블을 검색해 선택하면 해당 테이블의 집중 보기로 이동한다. **영역 전체로 돌아가기**로 원래 영역을 복원한다.
- 표시 좌표·묶음·연결점·관계선 경로는 DB 값을 읽는다. 선택 강조만 화면의 일시적인 상태다. 화면 조회로 배치를 생성하거나 덮어쓰지 않는다.

## DB 배치 저장

`app_setting`의 `erd:tns:layout:domain:<domain>`에 영역 배치, `erd:tns:layout:table:<table>`에 집중 보기 배치를 저장한다. 각 JSON에는 `version`, `revision`, `snapshotHash`, `savedAt`, `layout`, `routing`이 있다. 스키마 변경 없이 기존 JSONB 저장소를 사용한다.

영역 진입 시 해당 배치 한 건을 서버에서 읽는다. 집중 보기 전환 시 `/api/erd/tns/layout?domain=...&focus=...`로 필요한 한 건만 가져온다. 메뉴 요약에는 배치를 포함하지 않는다. 저장된 배치가 없거나 스냅샷이 달라지면 자동 계산으로 대체하지 않는다.

최초 등록은 읽기 전용 검사 토큰을 확인한 후 명시적으로 실행한다.

```sh
pnpm db:shared -- node scripts/erd-layouts.mjs inspect
pnpm db:shared -- node scripts/erd-layouts.mjs apply --expect <검사에서 받은 token>
```

`apply`는 누락된 배치만 등록한다. 원본 스냅샷·파생 ERD 문서·기존 배치는 보존하며, 이전 값과 생성할 키 목록을 `~/pm-backups`의 권한 0600 파일에 백업하고 SHA-256을 검증한다. 검사 이후 변경된 값이 있으면 중단한다. 기존 배치 수정은 좌표·연결점·경로를 함께 검증하고 revision을 올리는 별도 승인된 쓰기로 처리한다. 스냅샷 갱신 시 기존 배치도 명시적으로 갱신해야 하며, 이 초기화 명령은 오래된 배치를 자동 교체하지 않는다.

롤백 자료는 백업의 `state`와 `createdKeys`다. 복원 전 현재 값을 대조하고 이후 수정이 없는 생성 키만 제거해야 한다. 원본 스냅샷·문서 복원은 이 배치 등록의 롤백에 필요하지 않다.

`schema.mjs`는 현재 TNS 스키마의 단일 행 필드·관계 선언을 읽는 제한된 파서다. Prisma 전체 문법을 지원하는 범용 파서가 아니다. 스키마 문법이 바뀌면 파서와 검증을 함께 갱신한다. Prisma 명시적 FK만 포함하며 JSON/ID 문자열의 논리 관계, SQL 전용 제약, 실제 운영 DB와의 차이는 포함하지 않는다.

현재 웹 화면은 DB `app_setting`의 `erd:tns` 스냅샷을 읽는다. 이 디렉터리의 JSON은 최초 이관·테스트용 원본이다. 재생성만으로 배포 데이터가 바뀌지 않으며, 갱신 시 스냅샷과 `flow_document`의 ERD 차트를 함께 검증해 저장해야 한다.
