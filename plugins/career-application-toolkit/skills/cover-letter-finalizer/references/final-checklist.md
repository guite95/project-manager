# 제출 전 검수 기준

검수표는 작업 기준이다. 사용자에게 전부 출력할 필요는 없다. 원문·수정본·사용자 정정에 대조하여 실제로 확인한 범위만 완료로 표시하라.

| 항목 | 확인할 내용 | 정보가 부족할 때 |
| --- | --- | --- |
| 문항 | 원문과 필수 하위 질문에 모두 답함 | 문항 적합성 미검증으로 구분 |
| 지원동기 | 역할 설명 외에 지원 이유가 있음 | 개인 동기를 창작하지 않고 확인 필요 표시 |
| 두괄식 | 도입에서 구체적인 답을 알 수 있음 | 사실이 충분한 범위에서만 도입 재구성 |
| 근거 | 주장과 실제 경험·행동이 연결됨 | 새 사실을 넣지 않고 주장 강도 조정 |
| 개인 기여 | 팀 성과와 본인이 한 일을 구분함 | 단독·주도 표현을 확정하지 않음 |
| 수행 상태 | 계획·학습·진행·완료·운영을 구분함 | 보수적 시제로 단순 치환하지 말고 원래 상태 확인 |
| 수치·기간 | 출처와 일치하고 단위·시점이 유지됨 | 임의 수치를 삭제·보류하며 관련 성과 주장도 재점검 |
| 일관성 | 문항 간 사실·기술·조직명이 일치함 | 충돌 구간을 분리해 알림 |
| 문체 | 자연스러운 격식, 정확한 용어, 불필요한 반복 없음 | 기계적으로 동의어로 바꾸지 않음 |
| 분량 | 최종 본문을 최종 수정 뒤 실제 계산함 | 정확한 수치나 제한 충족을 단정하지 않음 |
| 제출 형식 | 편집 메모·표식 제거, 제목 처리 일치 | 제출 대상 본문 범위를 다시 구분 |
| 개인정보 | 확인된 블라인드·기밀 요구 준수 | 임의 규정·불필요한 민감정보를 추가하지 않음 |

수정 여부를 판단하기 위한 조건부 예시:
- 진단이 '배포 스크립트'를 'CI/CD 구축'으로 바꾸자고 했다면 반영하지 않는다.
- 원문의 핵심 문장이 이미 질문에 답한다면 두괄식을 강화한다는 이유로 추상적인 슬로건을 추가하지 않는다.
- 원고에 지원 이유가 없고 자료도 없다면 역할 소개를 더 매끄럽게 쓰는 것만으로 지원동기 누락이 해결되지는 않는다.
- 길이를 줄여 '연동 방식을 검토했습니다'가 '연동했습니다'로 바뀌었다면 상태가 달라졌으므로 되돌린다.
