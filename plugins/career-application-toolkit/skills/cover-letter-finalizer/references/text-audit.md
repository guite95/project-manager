# 본문 점검 도구

`scripts/text_audit.py`는 Python 3.9 이상 표준 라이브러리로 실행한다. 별도 패키지, API 키, 네트워크 연결이 필요하지 않다. 코드 실행 환경이 없으면 본문 작성·수정을 계속하되 계산을 하지 않고 정확한 글자 수를 보고하지 마라.

## 입력과 호출

문항별로 **실제 제출할 본문만** UTF-8 파일에 저장한 뒤 실행한다. 제출할 소제목은 포함하고 입력란에 넣지 않는 문항 원문·검토 설명은 제외한다. 파일을 만들며 붙인 마지막 줄바꿈도 실제 글자 수에 포함되므로 본문과 파일 내용이 같은지 확인한다. 실행 경로는 현재 읽고 있는 스킬 폴더 기준이며, 환경에서 확인한 절대 경로로 바꿀 수 있다.

```bash
# 공백과 원래 줄바꿈을 포함한 Unicode 코드 포인트 기준
python scripts/text_audit.py answer.txt --metric codepoints --max 1000

# 줄바꿈을 LF 하나로 처리하기로 명시한 경우에만 사용
python scripts/text_audit.py answer.txt --metric codepoints --newlines lf --min 800 --max 1000

# UTF-8 바이트 제한이라고 확인된 경우에만 사용
python scripts/text_audit.py answer.txt --metric utf8_bytes --max 2000
```

위 숫자는 실행 예시이지 기본 분량 조건이 아니다. 실제 문항 제한을 전달한다. 여러 문항이 있으면 하나의 파일로 합산하지 말고 문항마다 계산한다.

## 계산 기준

- `codepoints`: Python `len(text)`에 해당한다. 공백과 줄바꿈을 포함한다.
- `codepoints_no_ascii_spaces`: 일반 공백 U+0020만 제외한다. 탭·줄바꿈은 남는다.
- `codepoints_no_whitespace`: Python `str.isspace()`에 해당하는 공백·탭·줄바꿈 등을 제외한다.
- `utf8_bytes`: 선택한 줄바꿈 처리 후 UTF-8 바이트 수다.
- `utf16_units`: 선택한 줄바꿈 처리 후 UTF-16 코드 유닛 수다.

기본값은 원래 줄바꿈 보존이다. CRLF는 코드 포인트 두 개로 센다. `--newlines lf`는 CRLF와 CR을 LF로 바꾸고, `--newlines remove`는 CRLF·CR·LF를 제거한 뒤 센다. 위 세 종류 외 Unicode 줄 구분자는 이 옵션으로 바꾸지 않는다. Unicode NFC 정규화나 앞뒤 공백 제거는 자동으로 하지 않는다. BOM이 있다면 세고 경고한다.

지원 사이트의 산정 방식은 이 도구가 알아내지 않는다. 사이트 기준이 불명확하면 계산 방식을 표시하고, 사이트에서도 입력 후 확인이 필요하다는 점을 구분하라. 이 도구의 `within_specified_range`는 지정한 계산 방식과 경계 안에 있다는 뜻이며 지원 사이트의 통과 판정이 아니다.

## 미완성 표식

`[확인 필요]`, `[확인 필요: ...]`, `[미확인]`, `[회사명]`, `[직무명]`, `{{...}}`, `TODO`, `TBD` 등 일부 편집 표식 후보를 표시한다. 표시된 위치는 줄바꿈 옵션 적용 후 문자열의 코드 포인트 인덱스다.

후보를 문맥에서 확인하라. 표식이 없다고 미확인 사실이나 모든 빈칸이 없다는 뜻은 아니다. 본문에 남은 Markdown 강조·편집자 해설·다른 기업명은 별도로 읽고 확인한다.

## 결과의 한계

도구는 내용을 수정하거나 외부로 전송하지 않는다. 사실·의미·개인 기여·지원동기·문체·AI 작성 여부를 검증하지 않는다. 길이와 표식 결과를 편집 판단의 보조 자료로만 사용하라. 마지막 수정 뒤에는 반드시 다시 계산하라.
