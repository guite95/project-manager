# 문항 유형별 구성 기준

질문에 직접 답하는 데 필요한 유형만 사용하라. 아래 항목은 편집 기준이며 기업의 내부 채점표가 아니다.

| 유형 | 앞에서 답할 핵심 | 근거와 흐름 | 주요 실패 점검 |
| --- | --- | --- | --- |
| 지원동기 | 왜 해당 회사·직무를 선택하는가 | 확인된 관심·경험 → 관련 회사·직무 사실 → 하려는 일 | 역할 소개만 있고 지원 이유가 없음. 회사 홍보문을 개인 동기로 바꿈. |
| 직무역량·강점 | 어떤 역량을 어떤 경험으로 보여줄 것인가 | 문제·제약 → 본인 판단·행동 → 확인 결과 → 직무 연결 | 기술 목록만 있음. 결과는 크지만 개인 행동이 없음. |
| 협업·갈등 | 공동 목표에서 본인이 어떻게 행동했는가 | 실제 차이·문제 → 상대 관점 → 본인 제안·조율 → 결과 | 갈등·대화를 창작함. 상대를 무능한 사람으로 묘사함. |
| 도전·문제 해결 | 어떤 문제를 어떤 선택으로 다뤘는가 | 목표·제약 → 시도·수정 → 확인 결과 | 성공을 보장한 선택처럼 사후 미화함. 시도한 것과 성과를 섞음. |
| 실패·약점 | 실제 한계와 이후 무엇을 바꿨는가 | 본인 책임 범위 → 원인 → 개선 행동·확인 결과 | 실패를 억지 성공담으로 바꿈. 없는 실패를 만듦. |
| 성장·가치관 | 현재 행동을 만든 계기·기준은 무엇인가 | 실제 사건 → 변화 → 현재의 구체적인 행동 | 연대기만 나열함. 직무 연결을 위해 가족사·감정을 만듦. |
| 입사 후 계획 | 어떤 업무에 어떻게 기여·성장하려는가 | 확인된 업무 → 현재 역량 활용 → 현실적인 학습·책임 확대 | 근거 없는 연도별 승진·성과 수치를 약속함. |
| 복합 문항 | 두 개 이상 하위 질문 각각의 답 | 하위 질문을 문단·문장에 배정하고 연결 | 한쪽만 길게 답하고 다른 질문을 결론 한 줄로 대체함. |

지원동기 확인에는 다음 구분을 사용하라.
1. 회사 사실: 공식 자료에서 확인한 서비스·업무·방향.
2. 사용자 사실: 사용자가 말한 관심·경험·선택 이유.
3. 작성 제안: 두 사실을 연결할 수 있는 관점. 3을 2처럼 확정해 쓰지 않는다.

같은 프로젝트를 여러 문항에 쓸 때에는 실제로 서로 다른 행동이 있는지 확인하라. '기술 역량'과 '협업'처럼 제목만 달라지고 사건·행동·결론이 동일하면 재배치하라.
