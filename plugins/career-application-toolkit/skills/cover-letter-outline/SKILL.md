# 자소서 구성

## 선택적 MCP 품질 평가

사용자가 Jev 평가, JD 일치 점수 또는 평가 후 개선을 요청하면 [일반 Chat MCP 흐름](../../references/career-mcp.md)을 읽고 적용하라. 실제 연결된 도구만 사용하며 Work 전환을 요구하지 않는다. 초안·개요·문체 검토만 요청하면 기존 범위를 유지한다. 외부 전송과 평가용 스냅샷 보관 동의, 평가와 문서 저장의 구분, 중단 상태 처리에 이 연결 지침을 적용하라.

자기소개서를 쓰기 전에 **무엇을, 어떤 근거로, 어떤 순서로 답할지** 정하라. 결과는 문항별 개요이며 완성 본문이 아니다. 핵심 문장 예시는 허용하지만 개요만 요청받고 본문까지 자동으로 작성하지 마라.

작업 전에 [사실·문체 기준](references/evidence-and-style.md)을 읽어라. 문항 유형별 설계 시 [문항별 기준](references/question-types.md)을, 출력 전 [출력 템플릿](references/output-template.md)을 참고하라. 다음 단계로 넘길 때만 [전달 메모](references/handoff.md)를 참고하라.

## 1. 입력과 범위 확인

문항 원문, 분량 제한, 회사·직무, JD 분석 결과, 경험자료, 지원동기, 반드시 사용할 경험, 기존 개요·초안, 사용자 문체 선호 중 현재 있는 것을 확인하라.

- `jd-analyzer` 결과에 경험 매칭이 있으면 재사용하라. 동일 공고를 다시 분석하거나 경험 매칭용 새 스킬을 요구하지 마라.
- 앞 단계 결과 없이 문항과 경험만 있어도 설계하라. JD가 없으면 문항 기반으로 설계하고 직무 적합성 판단의 한계를 표시하라.
- 경험이 없으면 문항 해석과 빈 구조, 필요한 사실 항목까지 제공하라. 사용자 경험을 채워 넣지 마라.
- 문항이 없으면 접근 가능한 지정 자료부터 확인하라. 그래도 없으면 자유형 개요임을 명시하고 공식 문항을 지어내지 마라.
- 특정 문항만 요청받으면 다른 문항의 본문을 수정하지 마라. 전체 문항이 있을 때만 문항 간 배치를 함께 검토하라.

## 2. 문항을 답해야 할 요소로 분해

원문과 하위 질문을 유지하라. 예를 들어 '지원 이유와 준비 과정'은 두 요소 모두 답해야 한다. 질문에 없는 평가항목을 기업의 공식 채점 기준으로 주장하지 마라.

각 문항에서 답할 요소, 중심 메시지 하나, 그 메시지를 뒷받침할 경험을 연결하라. 지원동기·직무역량·협업·실패·성장·입사 후 계획 등 유형에 따라 설계를 바꾸고 모든 질문에 같은 경험 서술 틀을 강제하지 마라.

지원동기 문항은 '내가 어떤 개발자인가'나 '현재 무슨 일을 하는가'만으로 끝나지 않게 하라. 회사 선택 이유, 직무 선택 이유, 본인 연결을 문항이 요구하는 범위에서 구분하라. 개인 동기가 확인되지 않으면 사실인 척 첫 문장에 넣지 말고 구성 방향 후보와 확인사항으로 제시하라.

## 3. 경험 선정과 문항 간 배치

확인된 경험 중 문항에 직접 답할 수 있고 개인 행동을 설명할 수 있는 소재를 선택하라. 기술이 유행하거나 규모가 크다는 이유만으로 우선하지 마라. 주 경험은 필요한 만큼만 정하고 여러 경험을 얕게 나열하지 마라.

전체 문항을 함께 다루면 다음을 점검하라.

- 각 문항이 서로 다른 질문에 답하는가?
- 같은 프로젝트를 써도 실제 사건·행동·강조점이 구분되는가?
- 같은 행동과 결론을 문항마다 재사용하고 있지는 않은가?
- 좋은 소재를 모든 문항에 몰아넣거나 중복을 피하려고 약한 경험을 억지로 선택하지 않았는가?

지원 자격 충족과 서류에서 강조할 경험은 분리하라. 관련 경험을 선정했다는 이유만으로 필수 경력·자격을 충족했다고 쓰지 마라.

## 4. 두괄식 구조와 분량 설계

각 문항의 첫 문장에서 질문에 대한 답이 드러나게 하라. 추상적인 인재상·슬로건을 두괄식 답으로 대신하지 마라. 근거가 없는 결론은 작성 후보로만 표시하라.

문단마다 역할, 핵심 내용, 근거 경험, 목표 분량을 정하라. 배경은 행동을 이해하는 데 필요한 만큼만 쓰고, 본인 판단·행동과 질문에 대한 답에 분량을 배분하라. 필요한 경우 선택 이유, 결과, 이후 변화를 넣되 없는 사실을 만들지 마라.

분량 배분은 작성용 제안이지 기업 배점이 아니다. 합계가 입력 제한을 넘지 않게 하고 소제목·줄바꿈을 포함할지는 기준을 따로 표시하라. 실제 본문이 없으므로 정확한 최종 글자 수를 보고하지 마라. 고정 비율을 모든 문항에 적용하지 마라.

마지막 문장이 첫 문장의 단순 반복인지 점검하라. 이미 전달된 교훈·포부를 다시 붙이지 말고, 문항이 요구하는 성찰이나 계획은 빠뜨리지 마라.

## 5. 출력과 종료

기본 출력은 전체 배치 요약, 문항별 개요, 필요한 확인사항 순서다. 짧은 요청이면 요약표를 생략하라. 개요에는 원문·제한, 답할 요소, 핵심 답, 경험, 문단 설계, 주의할 사실을 포함하라.

최종 점검: 질문의 모든 요소, 실제 지원동기의 존재, 두괄식 답의 구체성, 개인 기여·수행 상태, 문항 간 중복, 분량 합계, 확인되지 않은 동기·성과를 확인하라.

사용자가 초안도 요청한 경우에만 작성 단계로 이어가라. `cover-letter-draft`가 실제로 제공되면 해당 지침을 읽고 개요·근거·제약을 전달하라. 접근할 수 없는 스킬을 호출했다고 말하거나 자동 실행을 보장하지 마라.
