# 자소서 초안 작성

## 선택적 MCP 품질 평가

사용자가 Jev 평가, JD 일치 점수 또는 평가 후 개선을 요청하면 [일반 Chat MCP 흐름](../../references/career-mcp.md)을 읽고 적용하라. 실제 연결된 도구만 사용하며 Work 전환을 요구하지 않는다. 초안·개요·문체 검토만 요청하면 기존 범위를 유지한다. 외부 전송과 평가용 스냅샷 보관 동의, 평가와 문서 저장의 구분, 중단 상태 처리에 이 연결 지침을 적용하라.

**개요와 확인된 경험을 실제 자기소개서 본문으로 작성하라.** 질문에 답하는 내용과 지원자 본인의 역할을 우선하고 문장을 꾸미기 위해 사실을 만들지 마라.

작업 전에 [사실·문체 기준](references/evidence-and-style.md)을 읽어라. 결과 구성에는 [출력 템플릿](references/output-template.md)을, 분량 검증에는 [본문 점검 도구](references/text-audit.md)를 참고하라. 단계 간 전달이 필요할 때만 [전달 메모](references/handoff.md)를 사용하라.

## 1. 작성 재료 확인

문항 원문·제한, 지원 회사·직무, JD 분석, 선택한 개요, 경험·개인 기여, 지원동기, 기준 글, 반드시 유지하거나 제외할 표현을 확인하라.

- 선택된 개요가 있으면 핵심 주장·경험 배치를 보존하라. 사실 오류나 문항 누락이 있으면 필요한 부분만 수정하고 중요한 변경을 알리라.
- 개요가 없어도 문항과 경험으로 짧게 구조를 정한 후 바로 초안을 작성하라. 개요 승인이나 특정 스킬의 실행을 불필요한 필수 절차로 만들지 마라.
- 여러 개요 중 선택하지 않았다면 사실이 충분하고 질문에 직접 답하는 안을 잠정 선택해 짧게 표시하라. 개인 동기나 민감한 사실을 선택이라는 이름으로 창작하지 마라.
- 제공된 기존 글을 다듬는 것이 주된 요청이면 초안 단계로 되돌리지 말고 수정 작업으로 처리하라. 선택한 스킬명보다 사용자의 실제 요청을 우선하라.

## 2. 사실 경계와 지원 이유 확정

작업에 쓸 사실, 개인 행동, 수행 상태, 확인 결과와 미확인 사항을 구별하라. 사용자 진술을 활용하되 과거 모델이 만든 주장을 재료로 승격하지 마라.

지원동기 문항이면 실제 지원 이유가 있는지 먼저 확인하라. 업무 수행 경험만으로 '왜 지원했는가'를 답했다고 판단하지 마라. 확인된 관심·경험과 회사·직무 사실을 연결하되, 사용자가 말하지 않은 열망·감정·어린 시절 계기를 만들지 마라.

핵심 근거가 부족하면 확인된 내용으로 작성 가능한 부분을 제공하고 미확인 사항을 본문 밖에 남겨라. 해당 문항을 완성할 수 없으면 '부분 초안'으로 표시하라. 사용자가 빈칸 양식을 요청하지 않은 한 `[지원동기 입력]` 같은 표식을 제출용 본문에 끼워 넣지 마라.

## 3. 본문 작성

1. 첫 문장 또는 첫 문단에서 질문에 대한 구체적 답을 제시하라. '저는 성장하는 인재입니다' 같은 자기평가로 답을 대신하지 마라.
2. 경험 배경은 행동을 이해하는 데 필요한 만큼 설명하라. 본인이 무엇을 판단하고 실행했는지 드러내라. 의사결정 이유가 없으면 합리적으로 보이는 이유를 새로 만들지 마라.
3. 기술은 이름보다 사용 목적·문제·행동과 연결하라. 단, 근거가 없는 목적·장애·규모를 덧붙이지 마라.
4. 팀 결과와 개인 기여를 구별하고 정량 성과가 없으면 확인된 산출물·변화를 사용하라. 계획이나 목표는 달성 결과와 다른 시제로 써라.
5. 문항이 요구한 성찰·준비 과정·계획을 빠뜨리지 마라. 이미 전달한 교훈과 포부를 매 문단에 반복하지 마라.
6. 소제목, 문단 수, 격식은 사용자 선호와 제출 양식에 맞추라. 자연스러움을 위해 억지 구어체·과장·오탈자를 넣지 마라.

문항별 어휘와 소재를 무조건 다르게 만들지 마라. 같은 프로젝트를 재사용해도 실제 행동과 답하는 관점이 다르면 가능하다. 전체 원고가 있으면 같은 사건·결론의 불필요한 반복을 조정하라.

## 4. 분량 조정과 검증

최소·최대·목표 분량을 구별하라. 사용자가 충분한 분량을 요청했는데 근거 없이 현저히 짧게 끝내지 마라. 짧으면 확인된 판단·행동·맥락을 보강하고, 길면 중복·불필요한 배경·상투적인 마무리부터 줄여라. 분량을 채우기 위한 새 경험이나 수치를 만들지 마라.

본문만 별도로 세어라. 제출되는 소제목은 포함하고 문항 원문·검토 메모는 입력란에 들어가지 않는 경우 제외하라. 정확한 수치는 실제 계산한 때만 표시하고 공백·줄바꿈·바이트 기준을 명시하라. 산정 기준이 없으면 공백·줄바꿈 포함 여부를 명시한 계산값을 제공하되 채용 사이트와 일치한다고 보장하지 마라.

실행 환경이 있으면 `scripts/text_audit.py`를 사용하라. 실행 환경이나 파일 접근이 없으면 같은 방식으로 계산할 수 있는 도구를 사용하고, 계산하지 못했으면 '정확한 글자 수 미검증'으로 표시하라. 스크립트가 사실·문체를 검증한 것으로 해석하지 마라.

## 5. 출력과 다음 단계

문항별 초안 본문을 먼저 제공하라. 그 뒤에 실제 계산한 분량, 필요한 사실 확인, 개요와 달라진 중요한 점만 짧게 붙여라. 본문만 요청받으면 불필요한 해설을 생략하되 제출을 오해하게 만드는 중대한 한계는 짧게 알리라.

출력 전 질문 충족, 지원동기, 두괄식 답, 개인 기여, 시점·상태·수치, 문항 간 중복, 분량, 남은 표식을 점검하라.

이 단계에서 `ai-killer` 진단 보고서나 최종 수정까지 자동 실행하지 마라. 사용자가 함께 요청하고 해당 스킬이 실제로 제공되는 경우에만 지침을 읽고 이어가라. 그때 초안과 함께 유지할 사실·표현 및 확인사항을 넘겨라.
